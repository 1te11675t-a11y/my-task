# プライベート タスク（iPhone用）

会社のPC版（`個人タスク管理/personal-taskboard.html`）とは**完全に別物**の、自分のiPhone専用アプリです。
GitHub Pages に置いて、Safariから開いて使います。

- **データはiPhoneの中だけ**に保存されます。サーバーには何も送りません（送る先がありません）。
- そのぶん、会社のPC版とは自動では同期しません。移したいときは書き出し／読み込みで手動です。
- データの形はPC版と同じなので、**書き出したJSONはPC版でそのまま読めます**（逆も同じ）。

---

## 1. iPhone向けに変えたところ

PC版をそのまま持ってきても、iPhoneでは動かない機能があります。次のように作り直しています。

| PC版 | iPhone版 |
|---|---|
| `tasks.json` に自動保存（File System Access API） | **iOSのSafariは非対応**。ブラウザ内に保存＋手動で書き出し／読み込み |
| ドラッグで移動・並べ替え | **タップ**で開き、「置き場所」を6つのボタンから選ぶ |
| 4象限のマトリクス画面 | 縦1列のリスト。**今日／一覧／カレンダー／予定**の4タブ |
| マウスを載せて詳細表示 | ホバーが無いので、行に必要な情報を直接出す |
| Ctrl+Z で取り消し | 操作直後に出る**「取り消す」ボタン**（トースト） |

そのほかiPhone向けの工夫：

- 入力欄は16px以上（Safariが勝手に拡大しないため）
- 下タブ・右下の＋ボタンは、片手の親指が届く位置。ホームバーの領域（セーフエリア）も避けています
- タップ範囲は指で押しやすい大きさ（1行あたり50px以上、右端に✓ボタン）
- ホーム画面に追加すると全画面のアプリとして開きます（アドレスバーが消えます）
- 圏外でも開けます（サービスワーカーでアプリ本体を端末に持っておきます）

## 2. 画面

| タブ | 中身 |
|---|---|
| ☀️ 今日 | 期限切れ／今日が期限／進行中／緊急・重要／1週間以内の発注・出張／回答待ち |
| 🗂 一覧 | 6つの置き場所（緊急・重要 … 着手前）ごとの一覧。「未完だけ／完了も表示／期限あり」で切替 |
| 📅 カレンダー | 月表示。日付に色の点が付き、日をタップするとその日の予定が下に出ます |
| 📦 予定 | 発注（見積もり中→発注済→検収済）と出張（調整中→申請済→清算済） |

- 行の右端の **✓** ですぐ完了。**↩** で戻せます。予定の✓は状態を1つ進めます。
- 完了したものは消えます。一覧タブの「完了も表示」で、**直近1か月ぶん**だけ戻せます。
- 右下の **＋** で追加。予定タブでは発注／出張／タスクを選べます。
- 右上の **⚙** がデータ画面（書き出し・読み込み・保存状況）です。

## 3. GitHub Pages で公開する手順

GitHubは初めてでも大丈夫です。**パソコンのブラウザだけ**で終わります（コマンドは使いません）。

### 手順A: アカウントを作る

1. <https://github.com> を開き、**Sign up**。メールアドレス・パスワード・ユーザー名を決めます。
   - ここで決めた**ユーザー名がURLの一部**になります（例: `yamamoto` → `https://yamamoto.github.io/...`）。
2. 届いたメールのコードを入れて登録完了。

### 手順B: 置き場所（リポジトリ）を作る

3. 右上の **＋** → **New repository**。
4. **Repository name** に名前を入れます。例: `my-tasks`
   （この名前もURLに入ります。推測されにくい名前でも構いません）
5. **Public** を選びます。
   > 無料アカウントでは、Publicでないと公開機能（Pages）が使えません。
   > 公開されるのは**アプリの画面だけ**で、タスクの中身は入りません（後述）。
6. 他は触らず **Create repository**。

### 手順C: ファイルを置く

ここが一番つまずきます。**いまどちらの画面にいるか**で入口が違います。

**C-1. 作った直後（ファイルが1つも無い）＝「Quick setup」画面のとき**

この画面には **Add file ボタンはありません**。画面の中ほどにある次の一文の、
**`uploading an existing file`**（青いリンク）を押してください。

```
Get started by creating a new file or uploading an existing file
```

**C-2. すでにファイル一覧が見えているとき**
（作成時に「Add a README file」にチェックを入れた場合）

ファイル名リストの**すぐ上の行**、右側にある緑の **`< > Code`** ボタンの**左隣**が
**`Add file ▾`** です。押して **Upload files** を選びます。

> ウィンドウが狭いと `Add file` の文字が消えて **`+`** アイコンだけになります。
> 見つからないときはブラウザを最大化してください。

**C-3. アップロード画面での操作**

7. 点線の枠に「Drag files here to add them to your repository」と出ます。
   ドラッグが不安なら、枠の中の **`choose your files`** を押すと、いつものファイル選択画面が開きます（こちらが確実）。
8. エクスプローラーでこのフォルダを開き、**中のファイルを選びます**（`Ctrl+A` で全選択）。

   ```
   index.html
   manifest.webmanifest
   sw.js
   icon-192.png
   icon-512.png
   apple-touch-icon.png
   ```

   ⚠️ **フォルダごとドラッグしないでください。** フォルダを入れるとGitHub上でも階層が残り、
   公開URLが `.../my-tasks/プライベートタスク_モバイル/` と深くなります。
   ⚠️ **tasks.json のような自分のデータは絶対に上げないでください。**
9. 選んだファイル名が縦に並びます。下の **「Commit changes」** 欄までスクロール。
   メッセージ欄は空のままで構いません（自動で `Add files via upload` になります）。
   ラジオボタンは **「Commit directly to the main branch」** のまま。
10. 緑の **Commit changes** を押します。
    リポジトリのトップに `index.html` などが並んで見えれば成功です。

### 手順D: 公開する

11. リポジトリ上部のタブ列（`Code` `Issues` `Pull requests` `Actions` …）の**右端**にある **⚙ Settings**。
    画面が狭いと `…` の中に隠れています。
12. 左メニューを下にたどって **Pages**（「Code and automation」の中）。
13. **Build and deployment** の **Source** を `Deploy from a branch` にします。
14. その下の **Branch** で、`None` のドロップダウンを **`main`** に変更。右隣は **`/ (root)`** のまま。**Save**。
15. 画面上部に公開URLが出るまで待ちます。**数分（最大10分）**かかります。ページを再読み込みして確認してください。
    進み具合は **Actions** タブの `pages-build-deployment` でも見えます。

    ```
    https://<ユーザー名>.github.io/<リポジトリ名>/
    ```

> **このパソコンで作ったリポジトリの場合**（ユーザー名 `1te11675t-a11y` / リポジトリ `my-task`）
>
> - アップロード画面: <https://github.com/1te11675t-a11y/my-task/upload/main>
> - Pagesの設定画面: <https://github.com/1te11675t-a11y/my-task/settings/pages>
> - 公開されるURL: <https://1te11675t-a11y.github.io/my-task/>

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| Settings に Pages が無い／設定できない | リポジトリが **Private** です。無料アカウントはPublicのみ。Settings → General の一番下 **Change visibility** でPublicに |
| URLを開くと 404 | ①まだ配信準備中（数分待つ）②リポジトリのトップに `index.html` が見えているか確認。フォルダの中に入っていたら、URLの末尾にそのフォルダ名を足せば開けます。直すなら、そのフォルダを削除してファイルだけ上げ直します |
| 真っ白な画面 | ファイル名の間違い。`index.html` は**すべて小文字**である必要があります |
| URLが見つからない | リポジトリ名は大文字小文字を区別します。作った名前どおりに入力してください |

### 手順E: iPhoneに入れる

14. iPhoneのSafariでそのURLを開きます（PCからAirDrop・メール・LINEでURLを送ると楽です）。
15. 下の**共有ボタン**（□に↑）→ **ホーム画面に追加** → 追加。
16. ホーム画面のアイコンから開けば、全画面のアプリとして使えます。

## 4. あとから直したくなったら

1. GitHubのリポジトリを開き、**Add file → Upload files**。
2. 直した `index.html` を同じ名前でドラッグして **Commit changes**（上書きされます）。
3. `sw.js` の1行目付近にある `const CACHE = "private-task-v1";` の数字を
   `v2`, `v3` … と増やしておくと、iPhone側が確実に新しい画面に入れ替わります。
4. iPhoneでアプリを開き直す（オンラインで一度開く）と反映されます。

## 5. 安全性について

| 心配 | 実際 |
|---|---|
| 公開URLだと誰かにタスクを見られない？ | **見られません**。GitHubに置くのは空のアプリ（HTML）だけです。タスクは各自の端末のブラウザに保存され、どこにも送信されません。他人がURLを開いても、まっさらな画面が出るだけです |
| 会社のデータが混ざらない？ | 別アプリ・別端末・別保存先です。混ざりません。会社のタスクをこちらに入れないよう、運用でだけ気をつけてください |
| 通信で漏れない？ | このアプリは外部への通信を一切しません（画面を最初に読み込むときだけGitHubから取得します） |
| リポジトリを非公開にしたい | GitHubの有料プラン（Pro）なら非公開リポジトリでもPagesが使えます。無料でやるなら、上のとおり**データを置かない**ので公開で問題ありません |

## 6. バックアップ（大事）

iOSのSafariは、**しばらく使わないサイトの保存データを消すことがあります**。
ホーム画面に追加して使うと消えにくくなりますが、念のため定期的に書き出してください。

- ⚙ →「⬇ ファイルに書き出す」… `tasks-2026-08-30.json` が「ファイル」アプリに保存されます
- ⚙ →「共有する」… メールやメモ、iCloud Driveへ送れます
- ⚙ →「コピーする」… JSONをコピー。メモ帳に貼っておくだけでもバックアップになります
- 戻すときは「⬆ ファイルから読み込む」または「貼り付けて読み込む」

データ画面に**最後に書き出した日時**が出ます。月に1回を目安に。

## 7. PC版とのやりとり

同期はしませんが、ファイルの形が同じなので手で移せます。

- **PC → iPhone**: PC版の「⬇ tasks.json を書き出す」→ そのファイルをiPhoneに送る（メール等）→ ⚙「⬆ ファイルから読み込む」。
  中身をコピーして「貼り付けて読み込む」でも入ります。
- **iPhone → PC**: ⚙「⬇ ファイルに書き出す」→ PCへ送る → PC版の「⬆ tasks.json を読み込む」。

> どちらも**全置き換え**です。両方で別々に編集したものを合体させることはできません。
> 会社用とプライベート用で中身を分けて使うのが前提です。

## 8. ファイル構成

```
プライベートタスク_モバイル\
    index.html              ← アプリ本体（これ1つで動きます）
    manifest.webmanifest    ← ホーム画面に追加したときの名前・アイコン設定
    sw.js                   ← 圏外でも開けるようにする仕組み
    icon-192.png            ← アイコン
    icon-512.png            ← アイコン
    apple-touch-icon.png    ← iPhoneのホーム画面アイコン
    README.md               ← この説明
```

データの形（`tasks` と `plans`）はPC版のREADME「データの形」と同じです。
